# Go2 高层步态项目学习路线

这份文档是从零重新理解项目时的固定入口。目标不是记住所有代码，而是逐步建立一条
清晰的信息链：

```text
任务与目标速度
→ 仿真和本体感知历史
→ 教师、学生和高层策略
→ 步态与连续参数
→ 冻结的 WTW 底层策略
→ 关节动作
→ 统一物理奖励
→ 强化学习更新
→ 独立评测
```

## 一、先明确项目目标

当前主线要验证的是：

```text
只使用目标速度和本体感知历史，
高层策略能否根据机器人实际运动状态，
选择步态并小幅调整连续步态参数，
在统一物理评价下优于固定 trot。
```

“不同地形必须出现不同步态”不是硬目标。成功至少需要满足：

1. 运动稳定，速度跟踪和安全指标不能明显退化；
2. 相比固定 trot，至少在部分合理场景有可重复的物理性能提升；
3. 推理时不使用任务编号、地形标签、步态答案、相机或雷达；
4. 如果最终主要选择 trot，也必须通过连续参数或局部步态变化产生实际收益，否则高层
   策略没有实用价值。

## 二、第一轮：只建立全局地图

### 1. 阅读 `README.md`

先理解：

- 项目依赖哪些基础设施；
- 高层网络的输入和输出；
- 为什么分成“先学步态、后调参数”两个阶段；
- 高层多久作出一次决策。

读完后，应当能用自己的话回答：

```text
高层网络看到了什么？
高层网络控制了什么？
底层 WTW 策略负责什么？
最终用什么对照判断高层策略是否有价值？
```

### 2. 阅读 `config.py`

重点记住：

- 四种步态：pronking、trotting、bounding、pacing；
- 五个连续参数：频率、触地时长、抬脚高度、站立宽度、身体俯仰；
- 高层环境一步是 `0.1` 秒；
- 步态更新周期只允许 `0.1～1.0` 秒；
- 当前统一奖励配置名称。

不要在这一阶段研究神经网络或强化学习公式。

## 三、第二轮：沿环境数据流阅读

### 3. 阅读 `tasks.py`

关注三个问题：

1. 训练任务和速度范围从哪里读取；
2. 多个并行环境如何分配给不同场景；
3. 为什么所有场景使用同一组奖励权重。

这里的统一奖励不是保证绝对公平，只是保证所有场景使用同一评价规则。指标定义、
归一化和权重是否合理，仍然需要独立审查。

### 4. 阅读 `low_level.py`

只需要理解：

```text
读取已经训练好的 WTW 模型
→ 恢复底层训练配置
→ 创建 Isaac Gym 环境
→ 冻结底层策略
```

现阶段不要深入底层 WTW 的训练过程。高层项目把它当作已经具备基本运动能力的执行器。

### 5. 阅读 `gait_wrapper.py`

建议分五段阅读：

1. `__init__`：四种步态模板、五个默认参数和允许的修正范围；
2. `_proprioceptive_frame`：一帧本体信息由什么组成；
3. `_mapped_action` 与 `_write_low_level_commands`：高层动作怎样变成 WTW 命令；
4. `_reward`：原始物理量怎样变成统一奖励；
5. `get_high_level_privileged_obs`：教师训练时额外读取哪 14 个仿真物理量。

读完后，手工画出：

```text
四维步态选择 + 五维参数修正
→ phase / offset / bound
→ frequency / duration / swing height / stance width / pitch
→ WTW command
```

### 6. 阅读 `environment.py`

这是组装层。重点理解：

- 如何创建每个地形对应的环境；
- 如何给每个环境采样目标速度；
- 为什么策略输入最后多了一维目标速度；
- 为什么学生只读本体历史，而教师可以读仿真物理量；
- reset 后目标速度如何重新采样。

完成这一轮后，应能解释一次 `env.step(action)` 内部发生了什么。

## 四、第三轮：理解网络

### 7. 阅读 `model.py`

先只看模块，不看概率公式。

```text
教师编码器：
14维仿真物理量 → 16维环境表征

学生编码器：
10帧本体感知历史 → 16维环境表征

物理状态预测：
学生表征 → 14维通用物理状态

步态选择器：
目标速度 + 16维表征 + 预测物理状态 → 四种步态概率

连续参数网络：
机器人状态 + 已选择步态 → 五个参数修正量

价值网络：
当前状态 → 未来累计奖励估计
```

然后再看四个关键函数：

1. `act`：训练时怎样随机采样步态和参数；
2. `act_student`：部署和评测时怎样只用学生确定动作；
3. `evaluate_actions`：训练更新时怎样重新计算动作概率；
4. `set_stage`：两个训练阶段分别冻结哪些模块。

需要特别记住：教师只在训练时使用，部署时不存在教师输入。

## 五、第四轮：理解强化学习训练

### 8. 阅读 `ppo.py`

PPO 在这里指“近端策略优化”，是一种限制每次策略更新幅度的强化学习方法。

先看 `RolloutBuffer` 保存什么：

```text
状态、教师物理量、动作、旧动作概率、
奖励、结束标记、价值估计、累计回报和优势值
```

“优势值”表示某个动作比当前价值网络预期得更好还是更差。

再看总损失：

```text
策略损失
+ 价值估计损失
+ 学生模仿教师的损失
+ 学生物理状态预测损失
+ 连续参数偏离默认值的惩罚
- 动作概率的熵奖励
```

这一轮不要求推导所有公式，但必须知道每项在训练哪个模块、解决什么问题。

### 9. 阅读 `train.py`

按程序执行顺序阅读：

```text
解析参数
→ 创建任务和环境
→ 创建或加载网络
→ 设置训练阶段
→ 收集一批运动数据
→ 计算累计奖励和优势
→ PPO 更新
→ 保存指标和检查点
```

重点理解两阶段训练：

```text
阶段一：
连续参数固定为默认值，只学习稳定的步态选择。

阶段二：
从阶段一模型开始，冻结步态选择和环境表征，
连续参数从零修正量开始做小范围调整。
```

这样做是为了避免训练早期“步态选错”和“参数扰坏”同时影响奖励，导致网络无法判断
奖励变化究竟来自哪一部分。

## 六、第五轮：理解如何证明效果

### 10. 阅读 `evaluate.py`

重点看：

- 如何固定任务和速度；
- 如何统计统一奖励、速度误差、摔倒率和步态比例；
- 如何用 `--force-gait trotting` 保持环境不变，只替换为固定 trot；
- 为什么自适应策略与固定 trot 必须使用相同种子和评测协议。

核心对照是：

```text
自适应高层策略
对比
固定 trot + 默认连续参数
```

不能只根据“出现了几种步态”判断成功，必须比较原始物理表现。

### 11. 阅读 `visualize.py` 和 `record.py`

这两个文件不参与训练：

- `visualize.py` 打开 Isaac Gym 界面；
- `record.py` 设置相机并保存视频；
- 视频只用于展示和发现明显异常，不能替代数值评测。

## 七、最后才阅读基础设施

完成最小主线后，再按问题阅读基础设施：

1. `go2_gym/envs/wrappers/high_level_reward_metrics.py`
   研究每个物理指标如何归一化，以及统一奖励如何加权。

2. `go2_gym/envs/wrappers/history_wrapper.py`
   研究底层观测历史如何形成。

3. `go2_gym/envs/base/`
   查找关节、接触力、足端速度、终止条件和仿真步长。

4. `go2_gym/envs/go2/`
   研究 Go2 机器人配置和底层速度跟踪环境。

5. 原 `scripts/`
   只在追溯历史实验时按需查阅，不再作为学习主线。

## 八、推荐动手练习

按照从低风险到高成本的顺序进行：

### 练习一：纸上追踪一次动作

任选 `trotting + residual=0`，手工算出：

```text
phase、offset、bound、frequency、duration、
footswing height、stance width、body pitch
```

### 练习二：打印网络尺寸

在 CPU 上构造随机张量，确认：

```text
本体历史：510维
加目标速度：511维
教师/学生表征：16维
步态输出：4维
连续参数输出：5维
总动作：9维
```

### 练习三：查看一行训练日志

能够解释：

```text
reward、vx_error、done_rate、
四种步态比例、四类训练损失
```

### 练习四：做一次短评测

比较同一地形速度下：

```text
自适应策略
固定 trot
```

先看统一奖励和速度误差，再看能耗、冲击、滑移等原始量。

### 练习五：最后才做短训练

先做很少迭代，确认：

- 环境可以启动；
- 奖励和损失都是有限值；
- 检查点可以保存并重新加载；
- 第一阶段连续参数确实为零；
- 第二阶段冻结模块确实不变化。

## 九、自检清单

能够回答以下问题，说明已经掌握主线：

- [ ] 高层一步、底层一步和十帧历史各代表多长时间？
- [ ] 51 维单帧本体观测由哪些部分组成？
- [ ] 14 维教师信息为什么只能在训练时使用？
- [ ] 四种步态如何编码成 WTW 的 phase、offset 和 bound？
- [ ] 五个连续参数为什么是默认模板附近的修正量？
- [ ] 统一奖励包含哪些物理目标，为什么统一不等于天然公平？
- [ ] 为什么先训练步态，再训练连续参数？
- [ ] PPO 的优势值在表达什么？
- [ ] 为什么步态多样性不能单独证明策略有效？
- [ ] 怎样用固定 trot 做公平对照？
- [ ] 哪些信息部署时可以使用，哪些只能在仿真训练中使用？

## 十、忘记现状时怎样恢复

以后重新进入项目时，只做四件事：

1. 阅读本文件和 `README.md`；
2. 按 `config → tasks → gait_wrapper → environment → model` 恢复信息流；
3. 阅读 `train.py` 和 `evaluate.py` 恢复训练与验证流程；
4. 查看最新运行目录中的配置、训练指标和独立评测结果。

不要从历史对话或原大型脚本开始。先恢复当前主线，再根据具体问题追溯历史。
