# Go2 项目汇报提纲

建议标题：基于本体感知历史的四足机器人高层步态自适应初步研究

## 第 1 页：问题与目标

页面内容：

```text
- 传统低层运动策略通常依赖固定步态或人工指定步态。
- 希望机器人只根据目标速度和自身运动历史，自主决定是否需要改变步态。
- 步态多样性不是目标；相对固定小跑改善物理性能才有价值。
```

口头说明：本项目不是为了展示更多步态，而是检验在不提供地形编号和步态答案时，
高层选择是否能带来真实收益。

## 第 2 页：整体系统

页面内容：

```text
目标速度 + 本体感知历史
        -> 学生历史编码网络
        -> 估计物理状态
        -> 高层步态选择器
        -> WTW 低层控制器
```

补充说明：训练时教师可读取干净物理量，部署时只保留学生；不使用相机、雷达、
任务编号、地形编号或目标步态标签。

## 第 3 页：统一评价与严格对照

页面内容：

```text
- 平地和上坡使用同一套物理奖励。
- 指标包括速度跟踪、存活、姿态、滑移、冲击、擦碰和机械功率。
- 对照组不是另训一个模型，而是在同一检查点上强制执行小跑。
- 地图、速度、随机种子、低层策略和运行长度保持一致。
```

口头说明：这种对照直接回答“自适应选择是否比固定小跑有用”，避免只看步态比例。

## 第 4 页：步态选择结果

使用 `core_result_figure.png` 左上图。

页面结论：

```text
- 平地超过 99.6% 使用小跑。
- 上坡低中速主要使用双脚跳。
- 随速度升高，上坡双脚跳比例从约 92% 降到约 46%。
```

口头说明：网络并非简单记住“上坡等于跳跃”，而是表现出速度依赖性；但这不
自动代表性能更好，必须看下一页。

## 第 5 页：相对固定小跑的性能

使用完整 `core_result_figure.png`。

页面结论：

```text
- 上坡 1.0 和 1.5 m/s：奖励更高，速度误差、接触滑移和冲击更低。
- 改善伴随机械功率增加，属于安全/跟踪与能耗之间的取舍。
- 平地几乎没有变化。
- 上坡 2.0 m/s 反而不如固定小跑，是当前方法的明确边界。
```

不要只展示奖励，必须同时展示功率代价和高速失败点。

## 第 6 页：训练机制控制实验

页面内容：

```text
- 全局回报基线也能学出上坡跳跃，因此按环境基线不是分化的必要条件。
- 全局模型在平地 0.5 m/s 约 17.8% 使用双脚跳，并额外消耗约 7.06 功率单位。
- 按环境基线模型在同一点仅约 0.31% 使用双脚跳，额外功率约 0.14。
```

口头说明：当前证据支持“按环境基线减少不必要的错误切换”，但训练随机种子数量
不足，不能把它宣称为普遍成立的新方法。

## 第 7 页：失败结果与局限

页面内容：

```text
- 三类连续参数网络均未取得超过仿真波动的稳定收益。
- 横向推扰未见场景泛化失败。
- 踏石只有很小且带安全代价的改善。
- 当前只在平地和上坡训练，尚无实机实验。
- 统一奖励仍是一套候选物理定义，不是绝对真值。
```

口头说明：这些负结果帮助确定了当前结论的边界，也是下一阶段研究问题的来源。

## 第 8 页：阶段结论与后续工作

阶段结论：

```text
仅依赖目标速度与本体感知历史，高层策略可以学到条件和速度相关的步态选择；
在中速上坡，相对固定小跑可改善速度跟踪和接触安全，但需要付出能耗代价。
```

后续工作：

```text
1. 重新研究连续参数为何缺少有效学习信号。
2. 提升未见地形上的物理状态表征与泛化。
3. 用更多训练随机种子验证训练机制，而不只增加评测随机种子。
4. 完成延迟、噪声和传感器偏差下的仿真到实机验证。
```

结束时不要声称“全地形自适应已经完成”，应称为“完成了局部有效原型和严格
性能验证，并明确了失败边界”。
